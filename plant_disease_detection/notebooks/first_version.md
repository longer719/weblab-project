植物病害检测系统项目结构与功能说明
总体架构
项目实现了一个完整的植物病害检测系统，包含两个核心功能：

植物种类识别 (分类)
植物病害检测 (目标检测)
系统采用前后端分离架构:

后端: Flask API服务，集成深度学习模型
前端: 原生JavaScript+HTML/CSS界面

目录结构：

├─ configs/             # 配置文件目录
├─ data/                # 数据目录

├─ models/              # 部署模型和映射文件

├─ scripts/             # 脚本文件(训练、处理等)
├─ src/                 # 源代码
│  ├─ api/              # API路由和处理
│  ├─ data_processing/  # 数据处理
│  ├─ evaluation/       # 评估工具 
│  ├─ inference/        # 推理相关
│  ├─ models/           # 模型定义
│  ├─ training/         # 训练相关
│  └─ utils/            # 工具函数
├─ static/              # 前端静态文件

核心组件
1. 机器学习模型
分类器 (plant_classifier.py)

基于ResNet101骨干网络
用于识别38类植物-病害组合
配置在plant_classifier_config.json
检测器 (disease_detector.py)

基于Faster R-CNN架构
使用ResNet50作为骨干网络
配置在disease_detector_config.json
2. 数据处理与映射
prepare_data.py

下载和处理PlantVillage数据集
创建训练/验证/测试集划分
生成类别映射文件
mapping_service.py

提供统一的映射服务
管理植物和病害类别映射
处理英文到中文名称的转换
3. 模型训练
train_classifier.py和train_detector.py

实现模型训练流程
支持从检查点恢复训练
集成评估和可视化功能
trainer.py

通用训练器类，处理训练循环和优化
支持各种训练策略
4. API接口
routes.py
/api/classify: 植物识别接口
/api/detect: 病害检测接口
/api/plant_info: 植物信息接口
/api/treatment: 治疗建议接口
5. 前端界面
main.js

处理用户交互和表单提交
实现图像上传和预览
管理API请求和响应处理
渲染分类和检测结果
visualization.js

提供检测结果可视化
支持边界框和热图展示
实现交互式阈值调整
6. 治疗与知识库
disease_treatments.py
定义病害治疗数据库
提供治疗方案和预防措施
支持植物-病害兼容性检查
系统工作流程
数据准备阶段

下载数据集 → 预处理 → 划分训练/验证/测试集 → 生成类别映射
训练阶段

加载配置 → 创建模型 → 训练 → 评估 → 保存最佳模型
部署阶段

选择最佳模型 → 部署到models目录 → 更新映射文件 → 更新版本信息
应用阶段

加载模型和配置 → 启动API服务 → 处理用户请求 → 返回分类/检测结果
系统当前问题
类别映射混乱

检测器在38类"植物-病害"组合上训练，但推理时错误使用21类纯病害映射
模型性能问题

置信度阈值(0.3)过低，导致低置信度的错误预测通过
泛化能力有限，对不同环境条件下的图像适应性不足
系统集成与交互问题

前端JavaScript代码存在全局范围执行的代码片段导致功能异常
植物病害治疗数据库未被充分利用
用户无法调整置信度阈值或控制检测结果精确性

一、项目概况与现状
项目架构
核心功能：植物种类识别 (分类) 和植物病害检测 (目标检测)
技术架构：Flask API后端 + JavaScript/HTML/CSS前端

检测器 (Faster R-CNN，ResNet50骨干网络)
主要问题
类别映射不一致：

检测器在38类"植物-病害"组合数据上训练，但推理时错误使用21类纯病害映射
分类器与检测器结果矛盾(如苹果-黑星病被误识别为桃子-细菌性斑点病)
模型性能：

置信度阈值过低(0.3)，允许低质量预测通过
泛化能力不足，特别是检测器模型
不同植物-病害组合的检测效果不一致
系统集成：

前端JavaScript代码存在全局执行问题
治疗建议数据库未充分利用
用户无法调整置信度阈值

风险管理
潜在风险与缓解策略：

数据质量不足：

风险：PlantVillage数据集可能无法覆盖所有真实场景。
缓解：实施数据增强和生成技术；考虑额外数据源补充。

风险：高级模型可能需要大量计算资源。
缓解：实现渐进式训练，先在小规模上测试再扩大；使用模型量化和蒸馏。
模型泛化能力风险：

风险：模型在真实场景中表现下降。
缓解：实施领域适应技术；构建更多样化的测试集；引入真实场景验证。
系统集成复杂度：

风险：多组件集成导致系统不稳定。
缓解：采用模块化设计；实施全面集成测试；建立系统监控。
